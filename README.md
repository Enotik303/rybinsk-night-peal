# Ночной перезвон Ростова

Практика по C++ на специальные функции класса и перегрузку операций. На неё заложено **2–2.5 часа**.

Нужно собрать партию ударов, у которой есть своя память, и провести из таких партий ночь. Партия умеет появиться, скопироваться, отдать память другому объекту и исчезнуть. Снаружи с ней говорят операциями: взять удар по номеру, сравнить, дописать, узнать длину в долях.

`Stroke` — просто два числа. Правил у него нет. Все правила живут в `Peal`.

## Что здесь относится к теме

- Конструктор умолчания, конструктор с параметром, список инициализации. `explicit`, чтобы `Peal p = 4` не компилировалось.
- Конструктор от массива. Его естественно начать с уже написанного `Peal(count)`, а не выделять память вторым способом.
- Копирование и перемещение. Деструктор забирает массив.
- Присваивание копированием и присваивание перемещением. Это не конструкторы: объект слева уже живёт и уже владеет памятью.
- `[]`, `==`, `!=`, `+`, `+=` и приведение к `int`. Старшинство операций не меняется: `+` не трогает слагаемые, `+=` меняет левый объект и возвращает его.

Наследования, виртуальных функций и шаблонов в решении не нужно. Хватает C++17 и `new` / `delete[]`.

## Сборка и тесты

Нужен компилятор с C++17 (g++ 7+, clang++ 5+) и CMake 3.16+. Из корня репозитория:

```bash
cmake -S . -B build
cmake --build build -j
./build/rostov_tests
```

То же самое одной командой: `make test`. Удалить сборку: `make clean`.

Без CMake:

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic -fsanitize=address -Iinclude -Itests \
  src/peal.cpp src/night.cpp \
  tests/main.cpp tests/test_life.cpp tests/test_assign.cpp tests/test_ops.cpp tests/test_night.cpp \
  -o rostov_tests
./rostov_tests
```

Сборка идёт с санитайзером адреса. Утечка, двойное удаление и обращение к уже отданной памяти — это красный тест, не предупреждение.

Зелёный прогон заканчивается строкой `итого: 23/23` и кодом возврата 0. На `main` лежат заглушки: они собираются. Зелёным сразу будет только пустой перезвон. Строка `ещё не написано` — честный провал, а не сломанное условие.

Тесты можно и нужно читать. Это часть условия. Править файлы в `tests/` нельзя.

Имена тестов сгруппированы: `life`, `assign`, `ops`, `night`. Имеет смысл чинить первую красную группу.

## Партия

Удар — это `bell` и `beats`. Партия их не проверяет: ноль, отрицательное число и большой номер одинаково законны. Ноль у свежего `Peal(n)` значит «ещё не заполняли», а не ошибку.

Память ударов принадлежит объекту. Два объекта не смотрят в один массив.

| Что | Как себя ведёт |
| --- | --- |
| `Peal()` | пусто, `size() == 0`, массива нет |
| `Peal(n)` | `n` нулевых ударов; `n == 0` — пусто; `n < 0` — `PealError` |
| `Peal(p, n)` | копия `n` ударов; `n == 0` допускает `p == nullptr`; иначе пустой указатель или `n < 0` — `PealError` |
| копия | свои удары. Чужой объект можно менять и уничтожать |
| перемещение | источник становится пустым: `size() == 0`, его можно уничтожить и присвоить в него снова |
| деструктор | освобождает массив. Пустая партия тоже уничтожается спокойно |
| `a = a` | партия остаётся той же |
| `a = std::move(a)` | партия остаётся той же |
| `a = std::move(b)` | `a` забирает удары, `b` пустеет. Старый массив `a` освобождается |

Текст `PealError` любой непустой: тесты проверяют тип. При ошибке объект, который уже жил, не меняется. Конструктор при ошибке не оставляет массив вызывающему.

`operator int` — сумма `beats`. Пустая партия даёт 0. Он `explicit`: длина в долях не подставляется молча в арифметику. Пишите `static_cast<int>(peal)`.

### Здесь легко промахнуться

Конструктор от массива лучше начать с `Peal(count)`. Тогда выделение написано один раз. Если `count > 0`, а указатель пустой, память к моменту ошибки уже есть: объект после чужого конструктора считается построенным, и деструктор её заберёт. Проверка указателя до выделения тоже годится, если при ошибке ничего не утекает.

`Peal(int)` и приведение к `int` объявлены `explicit`. `Peal p(4)` создаёт четыре нулевых удара. `Peal p = 4` не компилируется. Подумайте, что произошло бы с `p + 1`, если бы приведение было неявным.

В присваивании слева уже есть массив. `a = a`: если сначала сделать `delete[]`, копировать будет неоткуда. Сравнение `this == &other` здесь стоит до освобождения.

Перемещение — не обмен и не копия. После `b = std::move(a)` указатель остаётся только у `b`. Иначе деструктор `a` освободит память, которой уже пользуется `b`.

## Операции

`operator[]` возвращает удар. По отрицательному индексу и по индексу `>= size()` бросает `PealError`, партия не меняется. У константной партии есть своя константная версия: через неё удар читают.

`==` сравнивает число ударов и сами удары. Пустая равна пустой. Два разных объекта с теми же ударами равны: адрес массива ни при чём. `!=` — противоположность.

`a + b` — новая партия: сначала удары `a`, потом удары `b`. `a` и `b` остаются как были. Пустая партия в сложении ничего не добавляет.

`a += b` дописывает удары `b` в `a` и возвращает ссылку на `a`. Поэтому `a += b += c` сначала дописывает `c` к `b`, потом то, что получилось, к `a`. Дописывание пустой партии ничего не делает.

`a += a` удваивает партию: те же удары ещё раз в хвосте. Новый массив заполняют, пока старый ещё жив. `delete[]` после чтения, не до.

## Ночь

`ringNight` возвращает одну партию и на тестах не бросает исключений. Список на входе не меняется.

Пока в списке есть куски:

1. Пустой кусок пропускается.
2. Если кусок равен последнему уже взятому — его пропускают. Сравнение — это `==` партий, не «похож на всю уже собранную ночь».
3. Иначе кусок дописывается в ночь и становится последним взятым.
4. Пустой кусок последний взятый не сбрасывает. Следующая такая же партия всё ещё повтор.

Один кусок, даже если внутри него удары повторяются, не сжимается. Ночь склеивает куски, а не переписывает их.

### Два разбора

Куски: `A = (1, 2)`, пусто, снова `A`, `B = (3, 4), (5, 6)`, снова `B`, снова `A`.

Пусто между двумя `A` повтор не разрывает, второй `A` не берём. `B` другой, берём. Следующий `B` — повтор. Последний `A` уже не сосед предыдущему взятому. Ночь: `A`, затем `B`, затем `A`. Четыре удара.

Куски: `A = (1, 1)` и `A + A`.

Второй кусок — два удара, он не равен первому. Ночь из трёх ударов `(1, 1) (1, 1) (1, 1)`, а не из одного. Три `A` подряд, наоборот, схлопываются в один кусок.
