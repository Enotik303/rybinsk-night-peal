# Ночь на колокольне в Рыбинске

Ночью на колокольне в Рыбинске звонят по листкам. На листке записана партия: какие колокола бьют и как долго. Один удар — это номер колокола и число долей. Партия из двух ударов читается так: колокол 1 звучит две доли, потом колокол 3 звучит четыре доли.

Под удары каждого листка выделена своя память, и она принадлежит только ему. Сняли копию — у копии свой кусок памяти с теми же ударами, пометка на одном листе другой не портит. Отдали листок дальше — удары уходят вместе с памятью, у прежнего владельца остаётся пустая партия. Листок выбрасывают — память освобождается.

К утру звонарь складывает стопку листков в одну ночь. Пустой листок он пропускает. Если очередной листок совпадает с тем, который уже взят последним, второй раз его не звонят. Пустой лист между двумя одинаковыми эту пару не разнимает: второй всё равно повтор, и его пропускают.

В программе листок называется `Peal`, один удар — `Stroke`, сборка ночи — `ringNight`.

## Что нужно сделать

Писать нужно в двух файлах.

`src/peal.cpp` — сам листок. Он умеет:

- появиться пустым;
- появиться из `n` нулевых ударов, когда колокол и доли ещё не проставлены;
- появиться копией готового списка ударов;
- скопироваться, отдать свои удары другому листку и освободить память, когда его выбрасывают;
- принять чужие удары присваиванием;
- отдать удар по номеру, сравнить себя с другим листком, склеиться с ним в новый (`+`) и дописать чужие удары себе в хвост (`+=`);
- сказать, сколько долей он звучит целиком.

`src/night.cpp` — функция `ringNight`. На входе стопка листков, на выходе одна партия ночи. Сама стопка остаётся прежней.

Объявления методов уже стоят в заголовках, их не меняйте. Поля `strokes_` и `count_` тоже оставьте: в первом лежит память ударов, во втором — сколько их. Свой вспомогательный код можно держать в `.cpp` или добавить приватным методом в `include/rybinsk/peal.hpp`.

Проверка — тесты в `tests/`. Это то же условие, только примерами, поэтому их стоит читать. Править их нельзя. Группы идут по порядку: `life`, `assign`, `ops`, `night`. Ночь опирается на сравнение и `+=`, раньше них за неё лучше не браться. Если время кончилось, сдавайте те группы, которые уже зелёные.

## Как запустить

Нужен компилятор с C++17 (g++ 7+, clang++ 5+) и CMake 3.16+. Из корня репозитория:

```bash
cmake -S . -B build
cmake --build build -j
./build/rybinsk_tests
```

То же самое одной командой: `make test`. Удалить сборку: `make clean`.

Без CMake:

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic -fsanitize=address -Iinclude -Itests \
  src/peal.cpp src/night.cpp \
  tests/main.cpp tests/test_life.cpp tests/test_assign.cpp tests/test_ops.cpp tests/test_night.cpp \
  -o rybinsk_tests
./rybinsk_tests
```

Готовый прогон заканчивается строкой `итого: 23/23` и кодом возврата 0. На `main` написана только пустая партия, остальные тесты падают с текстом «ещё не написано». Так и задумано.

Сборка следит за памятью. Общий кусок памяти у двух листков, повторное освобождение и чтение удара из уже отданного листка приходят как красный тест.

Каталог `build/` и бинарник `rybinsk_tests` в git не кладите.

## Как устроен листок

`Stroke` — два целых числа: `bell` и `beats`. Листок не проверяет, есть ли на колокольне такой номер. Ноль и отрицательное число тоже можно записать. Свежий `Peal(n)` — это `n` ударов с нулями: колокол ещё не выбран и доли ещё не стоят.

Ниже точное поведение. На нём написаны тесты.

| Что происходит | Что получается |
| --- | --- |
| `Peal()` | пустой листок, `size() == 0`, памяти под удары нет |
| `Peal(n)` | `n` нулевых ударов; `n == 0` — пустой листок; `n < 0` — ошибка `PealError` |
| `Peal(p, n)` | копия `n` ударов из массива; при `n == 0` указатель может быть пустым; пустой указатель при `n > 0` и отрицательное `n` — `PealError` |
| копия | свои удары. Исходный листок можно менять и выбрасывать |
| перемещение | удары живут у нового владельца, источник пустой: `size() == 0`. Его можно выбросить и позже записать в него другую партию |
| деструктор | память освобождается. Пустой листок тоже спокойно выбрасывается |
| `a = a` | листок остаётся тем же |
| `a = std::move(a)` | листок остаётся тем же |
| `a = std::move(b)` | `a` забирает удары, `b` пустеет. Старая память `a` освобождается |

Текст `PealError` может быть любым. Тест проверяет тип ошибки. Если ошибка случилась у листка, который уже существует, его удары не меняются.

Сумма долей пишется как `static_cast<int>(peal)`. У пустого листка это 0. Четвёрка сама по себе листком не становится: `Peal p(4)` создаёт четыре нулевых удара, а запись `Peal p = 4` не компилируется.

Вот где обычно теряют удары.

В присваивании `a = a` слева и справа один и тот же листок. Освободите его память в начале — копировать будет неоткуда. Сначала проверьте, что это не один и тот же объект.

Когда листок дописывают к самому себе, `a += a`, старые удары ещё нужно прочитать. Сначала заполните новый массив, и только потом освобождайте старый.

После `b = std::move(a)` удары живут только в `b`. Если уход `a` освободит ту же память, `b` останется ни с чем.

Конструктор от массива удобно начать с `Peal(count)`: память выделяется в одном месте. Если элементов больше нуля, а указатель пустой, к моменту ошибки память уже может быть выделена. Деструктор её заберёт, объект к этому времени уже построен. Проверить указатель можно и раньше. При ошибке ничего не должно утечь.

## Как листки склеиваются

`a + b` — новый листок. Сначала идут удары `a`, за ними удары `b`. Сами `a` и `b` остаются как были. Пустой листок в такой склейке ничего не добавляет.

`a += b` дописывает удары `b` в конец `a` и возвращает сам `a`. В записи `a += b += c` сначала `c` дописывается к `b`, и уже этот результат дописывается к `a`. Пустой листок справа ничего не меняет.

`a += a` ставит те же удары ещё раз в хвост. Два удара становятся четырьмя.

`p[i]` — удар номер `i`, счёт с нуля. Его можно прочитать и заменить. Номер меньше нуля или номер от `size()` и дальше — ошибка, листок не меняется. У константного листка удар только читается.

`a == b`, когда ударов поровну и каждая пара совпала номером колокола и числом долей. Два разных листка с одной записью равны. Пустой равен пустому. `!=` означает, что листки различаются.

## Как собирается ночь

`ringNight` идёт по стопке сверху вниз и на тестах не бросает исключений.

Пустой листок она пропускает. Если листок равен последнему, который уже попал в ночь, она пропускает и его. Иначе дописывает листок в ночь целиком, и последним взятым становится он. Пустой листок этого «последнего» не стирает. Повторы внутри одного листка ночь не разбирает: она решает только, брать листок или перелистнуть.

Первая стопка:

1. колокол 1, две доли;
2. пустой листок;
3. снова колокол 1, две доли;
4. колокол 3 на четыре доли и колокол 5 на шесть долей;
5. тот же кусок, что в пункте 4;
6. снова колокол 1, две доли.

Пункт 3 совпадает с уже взятым пунктом 1, пустой лист между ними это не отменяет. Пункт 4 новый, его берём. Пункт 5 повторяет только что взятый четвёртый. Пункт 6 отличается от последнего взятого, его берём тоже. В ночи четыре удара: (1, 2), (3, 4), (5, 6), (1, 2).

Вторая стопка короче. Первый листок — один удар (1, 1). Второй — два таких удара подряд. Это уже другой листок: в нём два удара, а не один, поэтому в ночь попадают оба, всего три удара. А три одинаковых коротких листка подряд сожмутся в один: второй и третий просто повторяют первый.

## Как сдать

Работу сдавайте pull request в этот репозиторий, `ivashka27/rybinsk-night-peal`. Если открыть его в своём форке, в общий список он не попадёт.

1. Сделайте fork на свой аккаунт.
2. От `main` заведите ветку `solution/<github-login>`. В `main` форка решение не дописывайте.
3. Запустите тесты у себя. В отчёт попадёт сводка, в том числе если что-то ещё красное.
4. Запушьте ветку в свой fork.
5. Откройте pull request сюда: база `ivashka27/rybinsk-night-peal:main`, ветка — ваш `solution/<github-login>`.
6. Заголовок: `Рыбинск — Фамилия Имя`.
7. Текст возьмите из шаблона `.github/pull_request_template.md`.

В тексте нужны фамилия и группа, что успели, три короткие мысли из шаблона и последняя сводка тестов. Мысли пишите своими словами.

Во вкладке Actions форка один раз разрешите workflows. Проверка соберёт проект и запустит `./build/rybinsk_tests`. Локальный прогон всё равно нужен: в отчёт идёт его сводка.

В pull request не кладите `build/`, сгенерированный `ya.make`, дампы отладчика и чужие практики.
